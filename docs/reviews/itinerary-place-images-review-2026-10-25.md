# 行程地点图片展示验收

用户要求每个规划景点等地点直接展示一两张图片。前端已给真实活动/餐厅及明确酒店加入 PlaceImages，每处最多两张、去重、标注来源，可点击查看大图；自由用餐和住宿区域占位不冒充具体地点重复配图。

已有来源 image_urls 直接展示。旧无图计划进入可视区后异步请求只读 place-images 接口；图片不进入模型上下文，不为配图重新生成行程。无图、加载失败有占位，检索不可用可手动重试。旧请求在卸载/版本变化时中止，响应还须匹配版本和 evidence_id。保留上一轮卡片内展开酒店、美食的交互。

后端由另一聊天实现：只允许当前正式行程使用的景点、餐厅或酒店引用，优先已有图，无图仅查询同 POI ID 详情；过滤异城和不可用来源、拒绝伪造及过期版本，查询前后检查删除/改版。全局图片查询串行、有限队列、缓存和同请求合并，不写 Trip/消息/checkpoint、不调用规划模型。

## 验证

- 本聊天独立运行后端全量：373 passed，11 skipped（含 22 条新图片回归）。
- 本聊天另写 7 条临时独立反例通过：已有图最多两张不查地图不写库、旧版本提前拒绝、查询中改版拒绝、未使用/伪造引用拒绝、错 POI 不借图、并发共用一次查询和缓存。
- 前端 lint/TypeScript/production build 通过。
- 主站南京已保存行程：景点卡片直接显示来源实景图；核实南京博物院、六朝博物馆、颐和路图片 DOM complete 且 naturalWidth>0。实际样本来源各提供一张，未假造第二张。
- 隔离 5174 的 qa-place-photos-legacy 是前次真实北京 QA 计划的克隆，移除图片字段后测试旧计划补取。五道营胡同、府学胡同进入可视区后分别获取对应来源照片，图片加载成功；未滚到的地点尚未查询，不阻塞现有计划。
- 主 8000 加载新端点后，主站成都旧行程中的少城视井文创产业园区成功补图且实际加载。随后点击美食仍在 DAY 01 的 stop-detail 原位展开。
- 原北京会话未继续规划，实施聊天提供的运行检查证据确认重启前后四表哈希不变；主 health/MCP ok、5173 HTTP200。
