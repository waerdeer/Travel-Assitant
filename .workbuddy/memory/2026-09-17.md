# 2026-09-17

## 通读 Travel-Assistant 全项目 + 环境核验

### 架构梳理（供后续复用）
- 分层：React/Vite 前端 → FastAPI `app/api/routes.py` (`POST /api/v1/chat_plan`) → `app/agents/orchestrator.py`（只透传 thread_id + text）→ `app/graph/workflow.py` 编译的 LangGraph 图 → 外部依赖（高德 MCP over HTTP / DeepSeek / SQLite）。
- LangGraph 节点：`路由中枢 router_node` —(条件边 intent)→ `收集情报 info_agent` / `订机票酒店 booking_node` / `普通闲聊 chat_node`。
  - new_trip 主干道：收集情报 → 生成草案 → 订机票酒店 → 排最终行程 → END
  - modify_hotel 捷径：直接进 订机票酒店 → 排最终行程 → END
  - chat：普通闲聊 → END
- 三个 ReAct 子代理用 `langgraph.prebuilt.create_react_agent`，各自绑定专属工具集（INFO_TOOLS / BOOKING_TOOLS / PLANNER_TOOLS），`recursion_limit=5`。输出用 `with_structured_output` 回填成 TripState 严格字段。
- 工具是「胖包装」：`app/graph/tools.py` 把高德 MCP 的 `amap_maps_text_search` / `amap_maps_weather` 包成 4 个带 Pydantic schema 的工具。
- 记忆：`MemorySaver`（进程内存，重启即失）按 thread_id 存快照；`app/services/persistence.py` 做 write-through 落库（conversation / messages / trip 三表），失败不影响响应。

### 环境结论
- 本机可用环境：conda `langchain_project`（Python 3.10.20），依赖齐全且实测能导入 `app.main` 与编译 `app_graph`。
- 其他环境（base / stock / torchstudy / SciencePlotDrawing）均无该项目依赖。
- 前端 node_modules 已存在，node v22.22.2。

### 发现的问题（已告知用户）
1. **密钥泄露**：`.env.example` 被 git 跟踪且已 push 到公开仓库 `github.com/waerdeer/Travel-Assitant`，内含真实的高德 API Key 与 LLM API Key。建议立即轮换密钥并把占位符写回。
2. **仓库卫生**：`Frontend/node_modules` 共 8710 个文件被 git 跟踪，.gitignore 缺 `node_modules/`。
3. `MemorySaver` 是进程级内存，服务重启后多轮记忆全丢；DB 里存了消息但没做开局回灌。若要做持久多轮，需换成 SQLite/Postgres checkpointer。
4. `app/core/config.py` 用 class-based `Config`（Pydantic V2 已废弃，会报警告）。
5. `settings` 的 `env_file=".env"` 是相对 CWD 解析的，必须 `cd Backend` 后再起 uvicorn，否则读不到密钥。

## 「是不是 multi-agent」的定性结论
判定为 **Custom（路由式）多智能体**，非 Network / Supervisor 架构。
- 成立的：三个 ReAct 子代理角色分工明确、工具集隔离（INFO_TOOLS / BOOKING_TOOLS / PLANNER_TOOLS）、通过 TripState 黑板通信。
- 不成立的：router_node 只是 LLM 分类器（无工具、不能规划/委派）；图是 DAG 无回边，**agent 内部有 ReAct 循环、图层面没有循环**，因此无法跨节点重规划；三个子代理共用一个模块级 `llm` 实例，无异构模型。
- 记忆粒度：子代理是无状态一次性实例（每次节点调用内 `create_react_agent` 重建），跨轮记忆只靠 LangGraph state 快照 + 传入 `state["messages"]`。
- 宣称口径提醒：`main.py` 的 description 写「支持多领域 Skill」，但代码里没有 Skill 体系，`routes.py` 返回的 `skill_used` 实际就是 `intent`。对外讲项目时这是容易被追问的点。
- 升级为「真」多智能体的最小改动：把 router 换成可调用子图工具的 supervisor agent；在「排最终行程」后加 critique 节点并加回边；router 用便宜模型、planner 用强模型。
